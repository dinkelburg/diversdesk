## 00:03 Customer onboarding journeys overview

A customer onboarding journey contains everything a customer must complete before participating in an activity. This includes customer registration, agreeing to terms and conditions, signing waivers, and any additional actions included in the journey.

To configure journeys, open the Onboarding section from the hamburger menu. Start on the Form Builder page. From Forms, create registration forms and connect the waivers needed for the journey. A journey created on Forms can be connected to an individual activity, ensuring customers receive the correct paperwork for the activity they are joining.

## 01:09 Copying a default onboarding journey

Diversdesk provides default forms that can be copied to create a custom onboarding journey. For example, copy the Fun Diver journey, rename it to a clear operational name such as Certified Diver or Fun Diver, then select the registration fields and waivers to include.

The checkbox below image upload can make a journey available on the generic customer registration page. This page can be printed as a QR code for walk-in guests to scan and register themselves. For more detail about the available onboarding methods, refer to the documentation hub.

## 02:27 Adding waivers and configuring registration fields

Add the paperwork required before customers can participate, such as a diver medical, standard safe diving practices, or a release of liability. The generic upload section can add an upload field to the customer registration page; leave it empty when it should not be shown.

On the registration form, each field can be shown, made mandatory, or hidden. Review the fields needed for the journey, such as gender or BCD size. A field may be visible without being mandatory, for example the gear section. Save the journey to add it to Custom Forms.

## 03:58 Creating and understanding waivers

Open Waiver Builder from the hamburger menu to create waivers that can be included in custom onboarding journeys. A multi-language terms and conditions waiver marked Read is presented as a checkbox when connected to a journey. A waiver marked Signed is shown as a separate waiver that requires the customer's signature. Every waiver included in a journey is mandatory for the guest, whether its type is Read or Signed.

Create a waiver by choosing its type. Read creates a checkbox acknowledgment. Upload requires the guest to upload a file and is an alternative to an upload configured on the Forms page. Signature is a standard waiver requiring a customer signature. Configure a filing term to determine how long a signed waiver remains valid, for example one month for a rental gear contract.

## 06:07 Completing waiver content and languages

After creating a waiver type, use the Create link to define the actual waiver. Set an identifier, filing term, optional instructions for the guest, language, and display name. The display name is shown to the customer in their selected language; the identifier is used internally to recognize the waiver.

Waiver content uses Markdown. Use the Markdown cheat sheet in the documentation hub for formatting examples that can be copied into a custom waiver. Submit the language version, then add further versions under the same waiver for additional languages. Return to Form Builder and select the newly created signed waiver from the waiver dropdown to add it to the onboarding journey.

## 08:53 Connecting onboarding journeys to activities

After creating the journey, open the third page in Onboarding: Activity List. Connect the custom onboarding journey to every relevant activity, such as each fun-diving activity. The dropdown includes defaults and custom journeys created under the establishment.

Save the activity assignments so selecting a particular activity always presents the correct paperwork to the guest. Create additional journeys by copying appropriate defaults for courses or snorkel activities. Waivers are optional for each journey: for example, a beginner course form may only use terms and conditions when other waivers are handled by an application or certification organization.

## 10:37 Assigning course and snorkel journeys

Return to the Activity List and connect each newly created journey to its matching activity. In the example, a Discover Scuba Diving activity uses its dedicated journey, an Open Water activity uses the beginner course participant journey, and a snorkel activity uses the snorkel or non-diver journey. Once saved, guests receive the paperwork configured for the activity they select.

## 11:25 Using the generic registration page

The Form Builder checkbox that makes a journey selectable on the generic registration page should be used with descriptive journey names. On the generic customer registration page, a guest selects a journey themselves and is shown that journey's paperwork.

This is useful as a QR code displayed at the dive center, allowing guests to complete paperwork before a booking exists. In other cases, create a booking first and share it with the guest so the guest is scheduled on the correct date and connected to the correct activity.

## 12:22 Booking and customer registration flow

Create a booking from Bookings for the selected activity, enter a recognizable booking reference and participant count, then submit it. The booking includes registration slots. When the booking is shared with the guest, they can complete the onboarding journey.

In a customer-first or incognito view, the guest can use the registration link without being logged in. Available registration languages are automatically selected from the customer's browser settings. After completing the registration form, the guest must agree to the included terms and conditions and complete every required waiver.

## 14:04 Reviewing completed waivers and registrations

A signed waiver such as a rental gear contract is marked complete after the guest signs it and remains valid for its configured filing term, for example one month. Back in the booking, review that the customer has completed registration and all waivers. Open the customer's registration page to see the completed checkmarks and the onboarding journey connected to that activity.
